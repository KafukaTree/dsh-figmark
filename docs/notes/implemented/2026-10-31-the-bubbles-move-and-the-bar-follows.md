# Note: 气泡让开工具条，操作条从自己脚下开始拖

Status: implemented

## Problem

工具条、气泡、粗细滑轨都浮在图上，但它们的默认位置是各自定的，没有人替它们分过地方。工具条默认在左上角（`x .02 / y .04`，z-index 12），气泡栈也在左上角（`top 14 / left 14`，z-index 11）。工具条高一层，所以新读者看到的第一枚气泡，左侧的图标和一两个字被工具条盖住。

工具条与粗细滑轨在较矮的面板上也相交：工具条约 270px 高，从 4% 往下长；滑轨从面板中线往上长 100px。两者相交的条件是 `0.04H + 270 > H/2 − 100`，即 `H < 800px`。

还有两处同类的旧账：

- 面板一矮，`.da-palette{overflow-y:auto}` 会连拖柄一起滚走。拖柄是这条工具条唯一的拖动入口。
- `tests/styles.spec.ts` 有一条测试声称"让可拖动的工具条压在操作条上面"，断言却把两者都钉在 `z-index:12`。等层叠时后渲染的赢，也就是操作条赢——测试的注释描述了一个样式表没有的层序，而它一直是绿的。

另外在修这一处时发现：操作条的第一次拖动借的是 `barSpot ?? DEFAULT_PALETTE`，也就是工具条默认的那个角。操作条视觉上在底部，第一次拖动却从左上角起算，会瞬移。

## Decision

**工具条留在左上，气泡搬到右上。** 左上角是读者已经学会的位置（README 里叫"左侧浮条"），为了几秒钟的提示让每个读者重新学工具在哪，代价不对等。气泡是瞬态的那一个，它去右边空着的角：`.da-toasts` 从 `left:14px` 改成 `right:14px`，Markdown 正文的覆盖规则同步改成 `right:10px`。卡片本身也从 `left:0` 改成 `right:0`，否则短提示虽然住在右栏，却会贴在右栏左缘，看起来仍浮在中间。

同一批改了三处配套：

- **工具条的 z-index 提到 13**，严格高于操作条的 12。两条都可以拖，重叠时露在上面的那条必须先能被拖走；工具条在上，拖开它就露出操作条自己的拖柄。测试改成断言数字关系，不再钉两个字符串。
- **拖柄改成 `position:sticky; top:0`**，并用 `background:inherit` 取条体自己的底色。工具多到需要滚动时，瓷砖从拖柄底下穿过去，拖柄不会跟着消失；操作条永远不滚动，这条规则在它身上是空操作。
- **操作条的第一次拖动改成从它自己的盒子起算**（`spotOfBox`），已经停靠的条则继续从保存的 spot 起算。前者让默认在底边的条从读者看见的位置开始拖，而不是从工具条的默认角；后者避免宽条跨过中线时，用盒子中心反推锚点与真实渲染的 `transform` 矛盾而瞬移。换算用的面板取浮条的 `offsetParent`：PDF 把 chrome portal 到 `.da-pdf`，若用页面正文自己的 `.da-root`，初始位置和后续位移会落在两个不同的坐标系里。

## Alternatives considered

- **把工具条搬到右上** — 这是第一版改动。跑进真实宿主后它看起来不像当前产品：工具的位置是肌肉记忆的一部分，README 和读者都认左边。碰撞是真实问题，但解决它不该以移动最常用的控件为代价。
- **把工具条往下挪，让开气泡栈** — 气泡栈最高可以叠三张（约 160px），工具条再往下就会在矮面板上撞到操作条；两头都挤。
- **把气泡栈放回底部、操作条上方** — 气泡重新开始遮挡图的左下角，而且操作条 z 更高，气泡会被压在它后面。这正是当初把气泡移到顶部的原因。
- **只提高工具条的 z-index** — 工具条变得永远拖得动，但它仍然盖着气泡；顺序问题解决了，地方问题没解决。
- **把拖柄移出滚动区，做成固定的条头** — 效果和 sticky 一样，但滚动区里只剩瓷砖，条体的高度、圆角和阴影都要跟着重算。sticky 是同一个结果，不改布局。

## Consequences

- 气泡与工具条不再共用一角；提示也不会再盖住工具条。
- **工具条与粗细滑轨在 800px 以下仍会相交**，这是这次留下的唯一一处交叉。把滑轨搬到右边会改变绘图控件的方位，比它带来的好处更贵；工具条本来就可以被拖开。如实记在这里，没有假装解决。
- **HTML 的地址条仍是例外**：浮层按整块面板的百分比定位，而地址条是 `.da-root` 里第一个正常的流式子元素。在矮面板上，右上的气泡会在它出现的那几秒里压住右端的"回到这份文件"。气泡是瞬态的，地址条在那之后恢复；要彻底修，得给浮层换一个从 stage 起算的包含块。
- 操作条第一次拖动不再瞬移，而是从它当前所在的底部开始跟手。这一条是修 bug，不是新交互。
- 气泡搬到右上是一个可见的变化。若读者更看重提示与参考组件同角，可以只把这一条改回去；工具条的位置不依赖它。
