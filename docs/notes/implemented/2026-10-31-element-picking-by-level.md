# Note: 元素拾取从“碰运气”变成可看见的层级选择

Status: implemented

## Problem

元素模式过去只给出一个答案：浏览器命中的元素先向上找到最近的命名祖先，再把这个祖先当成唯一选择。对于 matplotlib SVG，一条细曲线旁边很容易命中 `axes_1`；对于 HTML，一个粗体词也只能升到所在段落。读者无法表达自己到底要曲线、整组 artist、段落还是外层容器，而且在点击之前不知道系统会选哪个。默认工具又是“选择”，所以第一次点击甚至不会进入拾取。点空白没有反馈，SVG 的悬停只有发光而没有名字，模式本身也没有解释。

## Decision

- 同一指针位置返回一条从精确绘制元素到稳定命名祖先的层级梯子。SVG 跳过没有稳定名字的中间 layout group；HTML 保留精确 inline 元素、默认可读块和后续包含块。
- 普通点击继续采用原来的默认层：SVG 取最近的稳定命名祖先，HTML 取可读块。元素模式下，`↑` 向父级走，`↓` 向子级走，点击采用当前层；`Esc` 退出元素模式。
- SVG 在悬停时除自身形状的光晕外再显示元素名，不画那个曲线并不占用的矩形框；HTML 继续同时显示名字和边界框。
- 图上只读的提示条说明当前是元素模式、当前层级和快捷键。提示条不接收指针事件。空白处按下时给出明确的“这里没有元素”反馈，而不是静默无响应。
- 默认工具仍是“选择”，但进入元素模式后，模式和可选层级会立即可见，不再依赖读者猜测图标含义。

## Alternatives considered

- **只把默认命中改成最细元素** — 曲线、文字节点和装饰 path 很容易选择到源码里难以定位的碎片，反而让最常见的“点部件”操作变差。
- **在点击后弹菜单列出祖先链** — 每次点击都多一步，菜单还要占在图像上；悬停加方向键可以在提交前直接看见选择。
- **SVG 也画矩形框** — 斜线、曲线和散点的外接框会覆盖大片没有绘制的区域，读者会以为框内全都属于该元素。保留形状光晕和名字更准确。
- **自动按面积或层级猜一个答案** — “最想选的那个”依赖读图意图，静态启发式无法区分一条曲线和它所属的坐标轴；显式层级让读者用一次按键决定。
- **改回默认进入元素模式** — 阅读和打开链接仍然应该沿用“选择”工具的手感；用可见提示解释如何进入元素模式，比改变整个默认模式便宜。

## Consequences

- 同一位置现在最多多出几个可选层，提示条会显示当前层与总层数；读者不必再靠反复试点。
- SVG 和 HTML 共用同一条层级规则和键盘手势，测试可以覆盖共享逻辑，而各文档仍保留自己的命中与 selector 规则。
- 元素模式多了一条覆盖在图上方的提示条。它只在模式启用时出现，且不拦截指针；在很矮的窗口里仍会占去少量图像顶部空间。
- 方向键只在元素模式下、且焦点不在输入框、文本域、下拉框或 contenteditable 中时生效；编辑评论时光标移动不受影响。
