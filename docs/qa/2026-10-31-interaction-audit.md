# dsh-figmark 交互与投递审计清单

基线：`435ed6e`（2026-10-31）

这份清单按“真实用户会怎样连续操作”组织，不按源码目录组织。目标不是证明已有测试
能通过，而是找出单元测试最容易漏掉的那类问题：第二步依赖第一步状态、两个异步结果
竞争、界面看起来成功但实际载荷不对、窗口变化后交互区域错位，以及失败以后工作丢失。

## 判定原则

1. **不丢工作**：任何失败都必须保留可重试的标注、评论、队列卡片和附件。
2. **所见即所发**：读者在清单、卡片和预览里看到的内容，必须和智能体收到的文字、
   图片、附件一致。
3. **单次正确不等于连续正确**：每项核心操作至少和“切换文档、再次发送、撤销、重试”
   组合一次。
4. **不能用替身的成功代替真实世界**：交互先用 jsdom 快速覆盖，最终仍要在真实宿主、
   真实浏览器与真实路由里走完。
5. **像素问题也算缺陷**：裁切、错位、遮挡、失去点击区域、不可读的短宽度布局都要
   记录，而不是当成“样式细节”。
